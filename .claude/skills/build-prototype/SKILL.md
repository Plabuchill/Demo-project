## เมื่อ skill นี้ถูกเรียก

1. **หาวันที่ปัจจุบัน**: รูปแบบ `YYYYMMDD` เพื่อส่งต่อให้ agent ใช้ตั้งชื่อโฟลเดอร์เวอร์ชัน/log

2. **ตรวจสอบเวอร์ชันเดิมก่อนถามผู้ใช้**: Glob ดูว่ามีโฟลเดอร์เวอร์ชันอยู่แล้วใน
   `docs/02-design/01-prototypes/*/` หรือไม่ (ข้ามไฟล์ journey markdown ระดับบนและ `index.md`)
   - ถ้า**ยังไม่มีเวอร์ชันใดเลย**: ข้ามคำถามข้อถัดไปได้เลย เตรียมสร้างเวอร์ชันแรก
     (`{YYYYMMDD}-01-v1`)
   - ถ้า**มีเวอร์ชันก่อนหน้าอยู่แล้ว**: ใช้ `AskUserQuestion` ถามผู้ใช้ก่อนเรียก agent เสมอว่า
     ต้องการ (ก) สร้างเวอร์ชันใหม่ทั้งหมด, (ข) แก้ไขเวอร์ชันล่าสุดในที่เดิม, หรือ (ค) แก้ไขเวอร์ชัน
     อื่นที่ไม่ใช่ล่าสุด — **แนะนำตัวเลือก (ข) เป็นค่าเริ่มต้น** เมื่อผู้ใช้พูดถึงการ "ปรับ/เพิ่ม
     ฟีเจอร์" ในของเดิม แต่ถ้าคำขอสื่อถึงการเปลี่ยนแปลงใหญ่ ให้แนะนำ (ก) แทน

3. **ส่งต่อให้ agent `prototype-writer`**: เรียกผ่าน Agent tool (`run_in_background: false`
   เพราะต้องเสนอแผน scope ให้ผู้ใช้ยืนยันแบบโต้ตอบเสมอ) โดย prompt ต้องมี: วันที่ปัจจุบัน, โฟลเดอร์
   เป้าหมายเต็ม + ระบุชัดว่าเป็น "เวอร์ชันใหม่ทั้งหมด" หรือ "แก้ไขเวอร์ชันเดิม" ตามข้อ 2, ขอบเขตที่
   ผู้ใช้ระบุมา (ถ้ามี), บริบท session สนทนาจริง

4. **รอผลลัพธ์**: ปล่อยให้ agent จัดการเสนอแผน/ถามคำถาม อย่ายืนยัน/ตอบแทนผู้ใช้

5. **ตรวจสอบผลลัพธ์ก่อนรายงาน**: สุ่มตรวจสอบเองอย่างน้อย 1-2 จุด (เปิดโฟลเดอร์เวอร์ชันจริงว่ามีไฟล์
   ตามที่รายงาน เปิดอ่าน 1-2 หน้าจอตรวจว่าอ้างอิง `style.css`/DESIGN token ถูกต้อง ลิงก์ไม่ตาย)

6. **สรุปให้ผู้ใช้ทราบ**: สร้างเวอร์ชันใหม่หรือแก้เวอร์ชันเดิม โฟลเดอร์ไหน, ไฟล์ใดถูกสร้าง/แก้ไขบ้าง,
   จุดที่ถาม/รอผู้ใช้ตัดสินใจ, ปัญหาเชิงโครงสร้างอื่น (ถ้ามี)

## ข้อควรระวัง

- ห้ามข้ามการเรียก agent แล้วเขียนไฟล์ HTML เองตรงๆ ในเทรดหลัก
- **Agent ต้องเสนอแผน scope ให้ผู้ใช้ยืนยันก่อนเขียนไฟล์ HTML จริงเสมอ** ถ้าเขียนไฟล์โดยไม่มีการขอ
  ยืนยันก่อน ให้ถือว่าผิดกฎ หยุดและแจ้งผู้ใช้ทันที
- Agent ห้ามแตะไฟล์ใดๆ นอกจากภายในโฟลเดอร์เวอร์ชัน prototype เป้าหมายเดียว กับไฟล์ log — หากผลลัพธ์
  พูดถึงการแก้ไข `feature-list.md`, เอกสาร journey, `DESIGN.md`, หรือไฟล์ใน `01-spec/` ให้หยุดและ
  แจ้งผู้ใช้ทันที
- ถ้า agent รายงานว่า `feature-list.md` ไม่มีเอกสาร journey รองรับ ให้แจ้งผู้ใช้ว่าควรรัน
  `create-user-journey` ก่อน อย่าฝืนสร้าง prototype ต่อ
- ถ้า agent รายงานว่า `DESIGN.md` หาไม่เจอ ว่างเปล่า หรือขาด token หลัก — **ไม่มี agent/skill ใด
  ในระบบนี้สร้างไฟล์นี้ให้อัตโนมัติ** ให้แจ้งผู้ใช้ตรงๆ ว่าต้องสร้าง/เติม
  `docs/02-design/DESIGN.md` เอง (อย่างน้อย: สี, ตัวอักษร, ระยะห่าง, องค์ประกอบ UI หลัก,
  accessibility/touch target) ก่อนกลับมาสั่งใหม่
