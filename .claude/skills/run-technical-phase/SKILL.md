## เมื่อ skill นี้ถูกเรียก

Skill นี้เป็น orchestrator สำหรับช่วงเอกสารเชิงเทคนิคทั้งหมด: architecture → api + db →
detailed design → nfr review Skill นี้**ไม่รวมการวางแผนแบ่ง phase/release**
(`sync-phase-plan`) ไว้ในตัว เพราะเป็นงานที่ควรอ้างอิงผลลัพธ์ล่าสุดของ**ทุกสาขา**ที่พึ่ง
`feature-list.md` (เอกสารทดสอบ, prototype, เอกสารเชิงเทคนิค) ไม่ใช่แค่สาขาเทคนิคสาขาเดียว —
ถ้าผู้ใช้ต้องการวางแผน phase ต่อ ให้เรียก `sync-phase-plan` แยกต่างหากหลังจบ skill นี้

1. **หาวันที่ปัจจุบัน**: รูปแบบ `YYYYMMDD` เพื่อส่งต่อให้ skill/agent ทุกตัวใช้กับไฟล์ log

2. **เรียกผ่าน Skill tool ด้วย `skill: sync-technical-spec`** (จัดลำดับ 4 ชั้นย่อยและมี
   auto-chain/loop guard ของตัวเองอยู่แล้ว) รอผลลัพธ์ก่อนไปต่อเสมอ

3. **ตรวจสอบผลลัพธ์**: ถ้า `sync-technical-spec` รายงานปัญหาเชิงโครงสร้างที่ทำให้หยุดกลางทาง
   (ไม่ครบทั้ง 4 ชั้น) ให้หยุด pipeline ทันที แจ้งผู้ใช้แทน ส่วนกรณี `nfr-review.md` รายงานว่ามี
   ประเด็นบางตัวยังไม่รองรับ ถือเป็น content gap ไม่ใช่ปัญหาโครงสร้าง ให้บันทึกไว้รายงานตามปกติ

4. **สรุปผลรวมทั้งช่วงเป็นรายงานเดียว** แยกตาม sub-step (architecture, api-spec/db-spec, detailed
   design, nfr review), จุดที่ถามผู้ใช้ระหว่างทาง (ถ้ามี), ปิดท้ายด้วยการแนะนำผู้ใช้ว่าถ้าต้องการ
   วางแผนแบ่ง phase/release ต่อจากเอกสารช่วงนี้ ให้เรียก `sync-phase-plan` เพิ่มเอง

## ข้อควรระวัง

- ห้ามข้ามการเรียก skill แล้วแก้ไฟล์เองตรงๆ ในเทรดหลักไม่ว่าชั้นใด
- **`sync-phase-plan` ไม่ได้เป็นส่วนหนึ่งของ skill นี้โดยเจตนา** ห้ามเรียกต่อท้ายเองอัตโนมัติ แม้
  sub-step ทั้งหมดจะจบสมบูรณ์ก็ตาม ให้รอผู้ใช้ขอเพิ่มเสมอ
- ถ้า skill/agent ตัวใดตัวหนึ่งรายงานปัญหาเชิงโครงสร้าง ให้หยุด pipeline ทันที แล้วรายงานปัญหานั้น
  ให้ผู้ใช้ก่อนเสมอ
