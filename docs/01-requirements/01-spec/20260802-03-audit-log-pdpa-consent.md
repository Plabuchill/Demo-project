# Audit Log และ PDPA Consent แบบเท่าที่จำเป็น

> สร้างเมื่อ: 2026-08-02
> สถานะ: Confirmed

## ที่มา (Background)

ผู้ใช้สอบถามแนวทางเรื่องการเก็บ log ของระบบและการปฏิบัติตาม PDPA ว่าต้องมีอะไรบ้าง ทีมงานให้คำแนะนำว่าโดยทั่วไปควรมี 2 ส่วน คือ (1) System/Audit Log และ (2) PDPA compliance แบบเต็มรูปแบบ (privacy notice, lawful basis, สิทธิเจ้าของข้อมูล, data retention, DPA กับ third party, มาตรการความปลอดภัย, breach notification)

ผู้ใช้ยืนยันว่าต้องการทำทั้ง 2 ส่วน แต่ในส่วน PDPA ขอทำ **เฉพาะ consent แบบง่าย** เท่าที่จำเป็น ไม่ต้องสร้างระบบ PDPA เต็มรูปแบบในระยะนี้ เนื่องจากร้านยังมีขนาดเล็กและต้องการควบคุมความซับซ้อนของระบบ

> **หมายเหตุ**: ตอนร่างเอกสารครั้งแรกมี 2 จุดที่ยังไม่มีคำตอบยืนยันจากผู้ใช้โดยตรง (ระยะเวลาเก็บ log และรูปแบบขั้นตอนการแสดง/กด consent) จึงตั้งเป็นสมมติฐานไว้ก่อน ต่อมาผู้ใช้ได้ตรวจสอบและ **ยืนยันค่าทั้ง 2 จุดตามที่ตั้งไว้แล้ว ไม่มีการแก้ไข** ดังตารางด้านล่าง (คงไว้เป็นบันทึกเหตุผลประกอบการตัดสินใจ)

### ค่าที่ยืนยันแล้วจากผู้ใช้

| ประเด็น | ค่าที่ยืนยัน | เหตุผล |
|---|---|---|
| ระยะเวลาเก็บ audit log (retention period) | 12 เดือน นับจากวันที่เกิดเหตุการณ์ จากนั้นลบ/archive อัตโนมัติ | เป็นระยะเวลาที่พอเพียงสำหรับตรวจสอบย้อนหลังกรณีข้อพิพาท/ปัญหาการชำระเงิน โดยไม่เก็บข้อมูลนานเกินความจำเป็น (สอดคล้องหลัก data minimization ของ PDPA) |
| รูปแบบขั้นตอนแสดง consent | แสดงเป็นข้อความสั้นพร้อมปุ่ม "ยอมรับ" ที่ลูกค้าต้องกดก่อนจึงจะดำเนินการชำระเงินต่อได้ (active consent แบบ blocking ขั้นตอนสั้น ๆ) | ปลอดภัยทางกฎหมายกว่าการแสดงเป็น banner แบบ passive เพราะมีหลักฐานว่าลูกค้ารับทราบและยินยอมจริงก่อนเก็บ/ประมวลผลข้อมูล แต่ยังคงเรียบง่าย ไม่ต้องมีระบบจัดการ consent ซับซ้อน |

## ขอบเขต (Scope)

- ทำ:
  - **System/Audit Log**
    - บันทึก log เหตุการณ์สำคัญของระบบ: การสร้างออเดอร์, การเปลี่ยนสถานะการจ่ายเงิน, การอัปเดตสถานะออเดอร์ (อ้างอิงขั้นตอนออเดอร์ใน [[../01-spec/20260802-01-table-self-order-qr|20260802-01-table-self-order-qr]])
    - บันทึก log การ login และการเข้าถึงหน้า dashboard ของพนักงาน/เจ้าของร้าน เพื่อเป็น audit trail ว่าใครเข้าถึงข้อมูลอะไรบ้าง โดยเฉพาะข้อมูลระดับสูงที่เฉพาะ role เจ้าของร้านเห็นได้ (อ้างอิงสิทธิ์การเข้าถึงที่กำหนดไว้ใน [[../01-spec/20260802-02-sales-dashboard|20260802-02-sales-dashboard]])
    - แต่ละรายการ log ต้องบันทึกอย่างน้อย: วันเวลาที่เกิดเหตุการณ์, ผู้ใช้/บัญชีที่เกี่ยวข้อง (ถ้ามี), ประเภทเหตุการณ์, และข้อมูลอ้างอิง (เช่น หมายเลขออเดอร์)
    - กำหนดระยะเวลาเก็บ log (retention period) ตามค่าที่ยืนยันด้านบน แล้วลบ/archive อัตโนมัติเมื่อครบกำหนด
    - จำกัดสิทธิ์การเข้าถึงตัว log เอง — เฉพาะ role เจ้าของร้าน/ผู้ดูแลระบบเท่านั้นที่ดู log ได้ พนักงานหน้าร้านไม่มีสิทธิ์เข้าถึง
  - **PDPA Consent แบบง่าย**
    - แสดงข้อความ Privacy Notice/ขอความยินยอม (consent) แบบสั้นกระชับ ให้ลูกค้าเห็นก่อนหรือระหว่างขั้นตอนชำระเงินออนไลน์ในระบบ QR self-order (อ้างอิง [[../01-spec/20260802-01-table-self-order-qr|20260802-01-table-self-order-qr]]) โดยบอกวัตถุประสงค์การเก็บข้อมูลแบบสั้น ๆ (เช่น เก็บข้อมูลออเดอร์และการชำระเงินเพื่อดำเนินการตามคำสั่งซื้อ)
    - ให้ลูกค้ากดยอมรับ/ผ่านขั้นตอนนี้ก่อนจึงจะดำเนินการชำระเงินต่อได้ (ดูรูปแบบ consent ที่ยืนยันแล้วด้านบน)
- ไม่ทำ (อยู่นอกขอบเขตของ requirement นี้ เพราะต้องการทำ PDPA เท่าที่จำเป็นเท่านั้น):
  - ระบบจัดการสิทธิ์เจ้าของข้อมูลแบบเต็มรูปแบบ (data subject access / rectify / delete request portal)
  - ระบบให้ลูกค้าถอน consent ภายหลัง หรือระบบจัดการ consent ที่ซับซ้อน (เก็บแค่หลักฐานว่ากดยอมรับแล้วเท่านั้น)
  - Data Processing Agreement (DPA) กับ third party เช่น payment gateway
  - แผน/ขั้นตอนแจ้งเหตุข้อมูลรั่วไหล (breach notification)
  - การแต่งตั้ง Data Protection Officer (DPO) อย่างเป็นทางการ
  - การเข้ารหัสข้อมูลขั้นสูงหรือมาตรการความปลอดภัยเพิ่มเติมนอกเหนือจาก access control ที่ระบุไว้ในเอกสารนี้

## รายละเอียด Requirement

1. ระบบต้องบันทึก log ทุกครั้งที่มีการสร้างออเดอร์ใหม่, เปลี่ยนสถานะการจ่ายเงิน (เช่น รอชำระ → ชำระแล้ว), และอัปเดตสถานะออเดอร์ (เช่น กำลังทำ → เสร็จแล้ว) โดยระบุวันเวลา, หมายเลขออเดอร์, และสถานะที่เปลี่ยน
2. ระบบต้องบันทึก log ทุกครั้งที่พนักงาน/เจ้าของร้าน login เข้าระบบ และทุกครั้งที่เข้าถึงหน้า dashboard ยอดขาย โดยระบุวันเวลา, บัญชีผู้ใช้, และ role ของผู้ใช้ เพื่อให้ตรวจสอบย้อนหลังได้ว่าใครเข้าถึงข้อมูลระดับเจ้าของร้านบ้าง
3. Log ทั้งหมดต้องถูกเก็บไว้ตามระยะเวลา retention ที่กำหนด (12 เดือน) แล้วลบ/archive อัตโนมัติเมื่อครบกำหนด เพื่อไม่ให้เก็บข้อมูลนานเกินความจำเป็น
4. เฉพาะผู้ใช้ที่มี role เจ้าของร้าน/ผู้ดูแลระบบเท่านั้นที่สามารถเข้าดู log ได้ ผู้ใช้ role พนักงานไม่มีสิทธิ์เข้าถึงหน้า/ข้อมูล log
5. ในขั้นตอนชำระเงินออนไลน์ของระบบ QR self-order ระบบต้องแสดงข้อความ Privacy Notice แบบสั้น บอกวัตถุประสงค์การเก็บข้อมูล (เช่น เพื่อดำเนินการตามคำสั่งซื้อและการชำระเงิน) และให้ลูกค้ากดยอมรับก่อนจึงดำเนินการชำระเงินต่อได้
6. ระบบไม่จำเป็นต้องมีหน้า/ฟังก์ชันให้ลูกค้าถอน consent ภายหลัง หรือจัดการ consent ที่ให้ไว้แล้ว — เก็บเพียงหลักฐานว่ามีการกดยอมรับ (เช่น timestamp) ควบคู่กับออเดอร์นั้น ๆ ก็เพียงพอ

## เกณฑ์การยอมรับ (Acceptance Criteria)

- [ ] ระบบบันทึก log เมื่อมีการสร้างออเดอร์ใหม่ พร้อมวันเวลาและหมายเลขออเดอร์
- [ ] ระบบบันทึก log เมื่อสถานะการจ่ายเงินของออเดอร์เปลี่ยนแปลง
- [ ] ระบบบันทึก log เมื่อสถานะออเดอร์ถูกอัปเดต (เช่น กำลังทำ/เสร็จแล้ว)
- [ ] ระบบบันทึก log เมื่อพนักงาน/เจ้าของร้าน login เข้าระบบ พร้อมบัญชีและ role ที่ login
- [ ] ระบบบันทึก log เมื่อมีการเข้าถึงหน้า dashboard ยอดขาย พร้อมบัญชีและ role ของผู้เข้าถึง
- [ ] Log ที่เก็บไว้เกินระยะเวลา retention ที่กำหนดจะถูกลบ/archive โดยอัตโนมัติ
- [ ] เฉพาะผู้ใช้ role เจ้าของร้าน/ผู้ดูแลระบบเท่านั้นที่เข้าดู log ได้ ผู้ใช้ role พนักงานเข้าถึงไม่ได้
- [ ] ลูกค้าเห็นข้อความ Privacy Notice/consent แบบสั้นก่อนหรือระหว่างขั้นตอนชำระเงินออนไลน์ในระบบ QR self-order
- [ ] ลูกค้าต้องกดยอมรับ consent ก่อนจึงจะดำเนินการชำระเงินต่อได้สำเร็จ
- [ ] ระบบไม่มีหน้า/ฟังก์ชันสำหรับถอน consent หรือจัดการคำขอสิทธิ์เจ้าของข้อมูลอื่น ๆ (อยู่นอกขอบเขต)
